SMI Tracker — маленький **внешний тренажёр и сборщик статистики** для Stalzone. Он считает
метрики прицеливания (флики, трекинг, дрожание, овершуты, мувмент) по движению мыши,
показывает дашборд и «скилл-оценку». Работает **отдельно от игры**: ничего не рисует поверх
и не вмешивается в игровой процесс.

- Платформа: Windows, C# / .NET 8, интерфейс на WPF.
- Одна внешняя зависимость — системный компонент Windows для шифрования токена (DPAPI).
- Никаких инъекций в процесс игры, драйверов или модификации клиента в проекте нет.

## Что программа делает

- Пассивно слушает движение мыши через стандартный механизм Windows (low-level hook) и
  считает метрики.
- Показывает дашборд и оценку **вне игры** (оверлея в игре нет).
- После привязки аккаунта читает **только свою публичную статистику профиля** через
  официальный API Stalzone (read-only GET), чтобы сверять метрики с реальной игрой.
- Отправляет **только агрегированные метрики сессий** на мой небольшой сервер для личного
  рейтинга/лидерборда. Игровые данные туда не уходят.

## Чего программа НЕ делает

- Не внедряется в процесс игры и не читает/пишет её память.
- Не рисует ничего поверх игры.
- Не эмулирует ввод: нет авто-кликеров, аим-ассиста, макросов и скриптов стрельбы.
- Не блокирует и не подменяет ввод — захват только «наблюдает» и всегда передаёт событие
  дальше (`CallNextHookEx`).
- Не меняет файлы игры и не даёт преимущества в бою. Это по сути тренажёр и статистика.

## Доп. Информация
Он анализирует движения мыши и рассчитывает различные показатели,
связанные с прицеливанием и движением:

• флики;
• трекинг;
• дрожание;
• овершуты;
• мувмент;
• другие показатели тренировочной сессии.

На основании этих данных программа показывает статистику, дашборд
и общий коэффициент.

Главное: Программа работает ОТДЕЛЬНО от игры.

Он не внедряется в игровой процесс, не изменяет игровой клиент,
не создаёт игровой оверлей и не выполняет игровые действия
вместо пользователя.

По сути, это тренажёр + сборщик статистики для анализа собственного
прицеливания.

• Платформа: Windows
• Язык: C# / .NET 8
• Интерфейс: WPF
• Сторонние драйверы: не используются
• Локальное шифрование: системный механизм Windows DPAPI 

## КАК РАБОТАЮТ ХУКИ

Для получения информации о действиях пользователя SMI Tracker
использует два стандартных системных механизма Windows:

• WH_MOUSE_LL — низкоуровневый хук мыши
• WH_KEYBOARD_LL — низкоуровневый хук клавиатуры

Это позволяет программе наблюдать за системными событиями мыши
и клавиатуры без внедрения в процесс игры.

ХУК МЫШИ — WH_MOUSE_LL

Хук получает события движения и нажатий мыши.

Для движения используются координаты X/Y и системная временная
метка события. Из последовательности таких отсчётов затем
рассчитываются тренировочные метрики.

Например:

движение мыши → последовательность отсчётов → математический анализ
→ флик / трекинг / овершут / дрожание и другие показатели.

Для этого программе не требуется доступ к памяти игры или её файлам.

Важно: хук не изменяет полученные события.

ХУК КЛАВИАТУРЫ — WH_KEYBOARD_LL

Клавиатурный хук используется для функций тренажёра, которым
необходимо знать состояние определённых клавиш.

Например:

• горячие клавиши программы;
• состояние клавиш движения;
• WASD;
• Space;
• Ctrl и другие необходимые клавиши.

Программа не использует хук для записи текста, который пользователь
печатает.

Ей важен сам факт нажатия или отпускания определённой клавиши,
а не содержимое вводимого текста.

## Важно!!!
Они работают в режиме НАБЛЮДЕНИЯ.

После обработки события программа передаёт его дальше через
стандартный механизм Windows CallNextHookEx.

То есть программа:

• не блокирует ввод;
• не изменяет ввод;
• не подменяет ввод;
• не создаёт дополнительные нажатия;
• не двигает мышь вместо пользователя.

Твой клик остаётся твоим кликом, а твоё движение мыши остаётся
твоим движением мыши.

При завершении работы программы установленные хуки корректно
снимаются через UnhookWindowsHookEx.

В коде хуков также отсутствуют механизмы создания искусственного
ввода вроде SendInput, mouse_event, keybd_event или
SetCursorPos.
